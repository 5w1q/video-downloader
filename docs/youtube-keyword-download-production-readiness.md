# YouTube 关键词下载 — 上生产前优化清单

> 日期：2026-07-10  
> 依据：`docs/smoke-youtube-keyword-download.md` + 本机复测  
> 范围：`YoutubeSearchSection` / `POST /api/youtube/search` / `POST /api/youtube/search-download`  
> 场景区分：**公网生产**（关 `LOCAL_MODE`、HTTPS、Ab/PG）用本文；**另一台本机生产**（保持 `LOCAL_MODE=1`）用 [`local-production-base-rules.md`](./local-production-base-rules.md)，只借用本文 P0 行为项（跳过/错误文案等）。  
> 结论（复测后）：代码侧 P0 与 Cookie+EJS 下载已可打通；公网全量上线仍须按本文关本地模式并补 P1。

## 1. P0 — 上线前必须修

### 1.1 浏览器模式下「跳过已下载」失效

**现象：** 默认勾选跳过 + 默认 `verify_file=true`；浏览器投递使用临时目录，文件下完即删，复跑时验本地文件失败 → 全部重新下载。

**根因：** `bulk_state.should_skip_url` 在 `verify_file=true` 时要求 `download_dir/filename` 仍存在；`resolve_bulk_output` 在浏览器模式下用 tempfile，且投递后删除。

**优化建议：**

| 方案 | 做法 | 推荐 |
|------|------|------|
| A（推荐） | 浏览器投递（`deliver_files=true` 且无持久目录）时，服务端强制按历史记录跳过，忽略验文件；或前端该场景默认 `verify_file=false` | ✅ |
| B | 持久化下载目录 + 验文件（适合「保存到服务器」） | 可选并存 |
| C | UI 明确文案：「仅在服务器保存目录存在时验文件；浏览器下载只按历史跳过」 | 与 A 一起做 |

**验收：** 同条件连跑两次，第二次成功 URL 全部为「跳过」，成功数不重复涨。

---

### 1.2 发布与进程一致性

**现象：** 冒烟时运行中的 uvicorn 仍是旧 schema（`date_filter` 仅 `all|today|date`），新代码已支持 `week|month`，导致指定日期探测 422。

**优化建议：**

- 生产禁止「改代码不重启」；Docker/K8s 用镜像 tag + 滚动更新。
- 健康检查增加版本/构建号接口（如 `/api/health` 返回 `git_sha` / `build_time`），发布后核对。
- 多 worker（`UVICORN_WORKERS>1`）时确认 ZIP 令牌、跳过状态文件在共享存储或进程间一致（当前令牌若仅内存/本地盘，多副本会 404）。

**验收：** 发布后 OpenAPI/`date_filter` 与文档一致；两副本轮询 ZIP 下载均成功。

---

### 1.3 生产配置与本地模式隔离

对照 `backend/.env.example` / `docker-compose.yml`，上线前确认：

| 项 | 本地常见值 | 生产要求 |
|----|------------|----------|
| `LOCAL_MODE` | `1` | **关闭** |
| `AB_BILLING_DISABLED` | `1` | **关闭**（若走正式计费） |
| `DATABASE_URL` | 空 / SQLite | PostgreSQL（多实例共享） |
| `FRONTEND_URL` / `CORS_ALLOWED_ORIGINS` / `APP_PUBLIC_DOMAIN` | localhost | 正式 HTTPS 域名 |
| `HTTP(S)_PROXY` | 本机 Clash | 生产出口代理策略明确、可故障切换 |
| `YTDLP_*` / cookies | 开发用 | 生产密钥进 Secret，不进镜像层 |
| `PERSIST_DOWNLOADS` | 视场景 | 与磁盘配额、清理策略一起定 |

**验收：** 未登录不可滥用搜索下载；计费/配额按产品规则扣减；CORS 仅白名单域名。

### 1.4 空结果与错误可解释（已有基础，需产品定稿）

冒烟中「今日」「指定日 + F1」可空，后端已返回扫描条数与原因。生产需保证：

- 前端完整展示服务端 `error.message`，不吞错、不卡死。
- 文案统一：可降阈值 / 改日期 / 改「不限」。
- 对「YouTube 限流 / 代理失败 / yt-dlp 异常」与「筛选无结果」区分展示。

## 2. P1 — 上线同期应完成

### 2.1 超时与长连接链路

冒烟：2 条视频常见数分钟到十几分钟。需整条链路对齐：

| 层 | 建议 |
|----|------|
| Nginx / 网关 | `proxy_read_timeout` ≥ 任务 P95（当前前端 nginx 600s，生产入口若另有 LB 也要改） |
| SSE | `proxy_buffering off`；禁中间层缓冲；心跳/注释行防空闲断开 |
| 后端 | yt-dlp `socket_timeout`、单条下载超时、任务总超时可配置 |
| 前端 | `fetch`/AbortController；超时提示「可取消后重试」，避免无限转圈 |

**验收：** 人为拖慢下载时，连接在配置超时前保持；超时后前端有明确失败态。

---

### 2.2 限流、配额与并发

| 风险 | 优化 |
|------|------|
| 单用户狂搜/狂下打爆出口 IP | 按用户/IP 限 QPS；搜索与下载分桶 |
| 多任务并行占满磁盘/CPU | 全局与每用户并发上限（建议下载串行或小并发） |
| 大 ZIP 占临时盘 | 临时目录配额、任务结束强制清理、磁盘水位告警 |
| 未登录或弱鉴权滥用 | 搜索/下载接口强制登录 + 配额 |

---

### 2.3 可观测性

最少指标：

- `youtube_search_total` / `youtube_search_empty_total`（按 `date_filter`）
- `youtube_download_ok|skip|fail`
- 单条下载耗时直方图、搜索耗时
- ZIP 注册/领取/二次 404 次数
- 代理错误、yt-dlp 错误码分类

日志需带：`request_id`、`user_id`、`query`（可脱敏）、`date_filter`、耗时、成功/跳过/失败。

告警：失败率突增、磁盘、代理连续失败、SSE 5xx。

---

### 2.4 ZIP 一次性与多实例

冒烟验证：首次下载成功，再次同链 404（符合设计）。生产注意：

- 令牌落盘目录需多 worker/多副本共享（NFS/对象存储元数据），或粘性会话。
- 浏览器可能对同一 URL 预检/双请求；已有 `peek`/`finalize` 设计时，确认生产路径走同一套，避免「第一次就被消费」。
- 大文件分卷：条数多或高清时测分卷下载与文案。

---

### 2.5 画质与默认参数

冒烟为加速使用了 `best[height<=360]`；生产默认若为 `bestvideo+bestaudio`：

- 耗时与体积显著上升 → 超时与磁盘压力放大。
- 建议：默认「标清/720p」可配；高级选项再开 best；或按套餐限制最高画质。

## 3. P2 — 体验与稳定性增强

| 项 | 说明 |
|----|------|
| 搜索结果缓存 | 同 query+筛选短时缓存，减少重复打 YouTube |
| 预览与下载一致性 | 前端「仅预览」后下载应复用已选 URL，避免二次搜索结果漂移（API `search-download` 会再搜） |
| 取消的服务端协作 | 前端 abort 后，当前条服务端可能仍在下；可加 job_id 取消 |
| 跳过状态迁移 | `bulk_download_state.json` 换机丢失；生产用 DB 存完成记录 |
| 日期时区 | 文档按东八区；生产服务器 TZ 固定 `Asia/Shanghai` 并写进部署文档 |
| 「今日」空结果率 | 产品侧引导默认「近一周」；或扩大 search_pool 并说明成本 |
| 与 X/Instagram 关键词下载对齐 | 跳过/验文件/超时策略三端一致，避免同产品不同行为 |

## 4. 安全与合规（生产基线）

- [ ] 关闭调试入口与 `LOCAL_MODE` 虚拟用户  
- [ ] Secrets（cookies、代理、DB、对象存储）不进 Git/镜像  
- [ ] 下载内容仅授权用户可得；ZIP/file token 短 TTL、一次性、不可枚举  
- [ ] 用户协议/版权提示：工具下载第三方平台内容的责任边界  
- [ ] 出口 IP 与代理账号监控，防止封禁导致全站不可用  
- [ ] 上传/表单大小、query 长度已有上限时保持；防 SSRF（缩略图代理等已有路径需复核）

## 7. 已知可接受限制（不必阻塞上线，但需告知运营）

- 搜索结果随 YouTube / yt-dlp 波动，「今日」易空。  
- 跳过依赖服务端历史；清库/换存储后行为变化。  
- ZIP 分卷仅在体积或文件数超阈值时出现；小任务多为单卷。  
- 浏览器模式与 ZIP 最终都进用户下载目录；差异是逐文件 vs 先打包。
